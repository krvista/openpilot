수정(opendbc_repo/opendbc/safety/sunnypilot/mads.h): 하트비트가 MADS 켜짐을 보고하고, 측면이 꺼져 있으며, 꺼진 이유(active_reason)와 보류 이유(pending_reasons)가 **둘 다 정확히 HEARTBEAT_ENGAGED_MISMATCH 하나**일 때만 controls_requested_lateral 을 다시 올린다. 요청은 기존 m_update_control_state 게이트를 그대로 통과하고, 다른 모든 해제 이유(버튼·브레이크·ACC main off·desync·lag)는 여전히 운전자 에지가 필요하다. 검증자 1차 BLOCK: active_reason 은 측면이 허용된 동안에만 갱신되므로 하트비트 회수 뒤 ACC main OFF / desync / 브레이크가 겹치면 active_reason 이 32 로 남아 재허용될 수 있었다(재현됨) → pending_reasons 조건 추가로 닫음(브레이크 해제 재요청과 같은 패턴). 패널의 하트비트 검사는 1 Hz(main.c 의 loop_counter==0 블록)라 회수까지 ~3 s, 재허용은 ≤ ~1.1 s — selfdrived 의 2 s 불일치 카운터 안에 든다(디바운스를 넣으면 창을 놓쳐 채택 안 함). 2차 검증 SHIP 의 잔여 권고도 반영: 하트비트 검사(1 Hz)가 요청을 올린 뒤 다음 CAN 메시지가 소비하기 전의 틈에 브레이크/ACC main OFF/오버라이드 해제가 오면 래치된 요청이 살아남아 허용될 수 있었다 → mads_exit_controls 가 측면 허용 여부와 무관하게 보류 요청을 항상 버리도록 변경(브레이크 해제 재요청은 같은 패스에서 해제 뒤에 세워지므로 영향 없음). 테스트(mads_common.py): 재허용 정상 경로(ACC main 켜진 채, tick + _rx 두 경로), 다른 해제가 겹친 6가지 이유 전부 거부, 래치된 요청이 ACC main OFF/브레이크/오버라이드 해제로 버려짐, MADS 꺼진 빌드 거부(pending 도 HEARTBEAT 로 맞춘 뒤); 옛 코드·active_reason 만 보는 코드에서 각각 실패 확인; hyundai_canfd + i6n 스위트 2126 passed. ## 10. panda faultTemp(interruptRateCan2) — 원인과 개선

**원인.** 부팅 시 pandad(파이썬 Panda 생성자와 C++ Panda 생성자, 두 번)가 `can_reset_communications` 를 부르면 펌웨어 `can_init_all` 이 `canfd_enabled=false` 로 세 버스를 **클래식 CAN 으로** 초기화한다. 버스 1(초당 3,350 프레임, CAN-FD 2 Mbit)은 그 순간부터 `set_data_speed_kbps` 로 FD 가 다시 켜질 때까지(1.5–2 s, 두 창) 모든 프레임이 stuff/form 오류 → 오류 인터럽트 폭주. 라우트 f seg 0: 4.9–6.5 s 와 6.8–7.3 s 에 오류 3.3만 건, FDCAN2 IRQ 초당 18,298 (한도 CAN_INTERRUPT_RATE 16,000) → `FAULT_INTERRUPT_RATE_CAN_2`. 라우트 e 는 같은 폭주가 12,088/s 로 한도 아래여서 폴트 없음 — 그날그날 운. IRQ 속도 폴트는 `fault_recovered` 가 불리지 않아 주행 내내 래치된다(f 40 seg, 11 29 seg).

**영향.** 기능 영향 없음: `PERMANENT_FAULTS = 0`, 폴트는 health 패킷(faultStatus/faults)과 DEBUG_FAULTS LED 에만 쓰이고 openpilot 은 relayMalfunction 외에는 보지 않는다. 주행 중 버스 1 IRQ 는 3.2k/s, 인터럽트 부하 0.30 으로 정상. 폭주 자체는 부팅 2 s 동안 panda 가 error-passive 로 갈 때까지 active error flag 를 버스에 내보내는 것이 유일한 실질 부작용(다른 ECU 의 수신 오류 카운터 소폭 상승).

**개선 (펌웨어, 두 줄 수준).**
1. `can_init_all` / 0xde(set can bitrate)에서 `canfd_enabled` 를 강제로 false 로 두지 말고 설정값에서 유도: `canfd_enabled = (can_data_speed >= can_speed)` (기본 20000 ≥ 5000 → FD). FD 코어는 클래식 프레임도 정상 수신하므로 클래식 전용 버스에 해가 없고, FD 버스에서는 클래식 창 자체가 사라져 폭주와 폴트가 없어진다. TX 는 `canfd_auto=false` 라 패킷의 fd 플래그를 그대로 따르므로 변화 없음.
2. `interrupt_timer_handler` 에서 1 s 카운터가 한도 아래면 `fault_recovered(call_rate_fault)` — 일시 폴트를 이름대로 일시적으로. (선택) `update_can_health_pkt` 에서 초당 오류 N건 초과 시 PEDE/PEAE 인터럽트를 다음 can_init 까지 마스크해 폭주 자체를 끊음.
